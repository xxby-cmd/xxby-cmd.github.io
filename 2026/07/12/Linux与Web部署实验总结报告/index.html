总结报告：Web软件部署综合实验

姓名：贾国龙　　学号：22070809
实验环境：Windows 11 专业版 25H2 + VirtualBox + Ubuntu Server 22.04 LTS

一、实验目的与概述

本课程旨在让我们学习web软件部署的全流程，并了解虚拟机和linux系统的相关知识，这几天，我完成八个子实验，围绕 Web开发环境搭建 → Linux系统基础 → 远程管理 → Web站点部署 这一完整过程展开，形成了一套完整的”开发—测试—部署”实践闭环。

二、实验过程

2.1 Web运行环境

2.1.1 Node.js与npm环境

  • 我安装 Node.js 24.18.0 、npm 11.16.0 作为运行环境，同时采用国内镜像源解决国外下载速度慢的问题。

2.1.2 Hexo博客框架

首先要注意的是全局安装Hexo-CLI 静态站点生成工具，然后初始化博客项目，安装项目依赖，生成标准Hexo目录结构

  • 本地预览服务：hexo server
  • 静态文件生成：hexo generate

2.1.3 主题与扩展

  • 安装并配置 NexT主题，通过修改配置文件实现不同风格切换，并理解静态站点的核心原理：本地代码 → 构建工具 → 纯HTML/CSS/JS静态文件 → Web服务器展示

2.2 项目与代码库配置

2.2.1 编辑器配置（VS Code）

  • 我安装 VS Code 作为主要编辑软件，并安装了安配置四大核心插件：
    • Markdown All in One
    • Markdown Preview Enhanced
    • Paste Image
    • MarkdownLint

2.2.2 Git配置与代码管理

然后，我安装 Git 2.55.0，并选择VS Code作为默认编辑器，掌握Git核心工作流：初始化仓库（git init）、添加暂存（git add）、提交版本（git commit）、关联远程（git remote add）、推送代码（git push）

2.2.3 项目结构管理

Hexo博客项目采用标准的Node.js项目结构，并实现源码仓库（my-blog1）与部署仓库（xxby-cmd.github.io）分离，通过GitHub Actions实现代码推送后的自动构建与部署。

2.5 Web站点部署

2.5.1 双仓库部署

采用 源码仓库 + 部署仓库 的设计：

仓库类型 仓库名 权限 用途
源码仓库 my-blog1 Private 存放Hexo源码、配置文件
部署仓库 xxby-cmd.github.io Public 托管构建后的静态页面

2.5.2 CI/CD流水线

工作流文件：.github/workflows/deploy.yml

步骤：

  1. 检出源码：拉取main分支代码
  2. 生成静态文件：执行 npx hexo generate，构建public目录
  3. 创建.nojekyll文件：跳过GitHub Pages的Jekyll处理
  4. 部署到GitHub Pages：将public目录推送到部署仓库

触发条件：

  • 自动触发：向main分支推送代码时自动执行

2.5.3 Token与权限配置

生成 Personal Access Token，在源码仓库配置Secrets：PERSONAL_TOKEN，部署仓库开启GitHub Pages，分支选择main，根目录发布

2.5.4 验证部署

  • 最终站点可通过 https://xxby-cmd.github.io 公网访问，并且只需要本地 提交推送即可完成发布 的自动化流程，

三、实验技术链路总览

四、遇到的问题与解决方案

序号 问题描述 解决方案
1 国外软件下载速度慢、部分网站无法访问 改用国内镜像源下载
2 YAML配置文件缩进错误导致配置失效 严格遵循YAML缩进规范，使用空格而非Tab，逐行检查对齐
3 Markdown语法不熟悉，表格、公式等格式不会写 配合MarkdownLint插件边写边校验
4 虚拟机之间ping不通，IP地址冲突 重启虚拟机，检查各节点静态IP配置是否唯一，确认hosts解析正确
5 环境变量配置后不生效 区分临时/永久、用户级/系统级，配置后执行source或重新登录终端
6 GitHub Actions部署失败，权限不足 检查Personal Access Token权限范围，确认Secrets配置名称与工作流引用一致
7 部署步骤多、逻辑不清晰，容易一步错步步错 按模块拆解理解每一步作用，从原理层面掌握CI/CD流程而非机械照搬

五、心得体会

5.1 收获

  1. 完整流程认识：我从一开始根本不知道干什么，无从下手，到慢慢安装环境、VS Code编辑文档，慢慢的了解hexo博客软件，以及GitHub代码管理，慢慢的认识了一些web部署的内容，虽然现在还是雾里看花，但是已经稀里糊涂的完成一个完整操作，这也对我的下一次更多学习知识有了更一步的促进。
  2. Linux命令行能力：我一开始根本不知道linux系统是什么，后来逐渐明白了命令行操作的内容，以及一些基础命令如文件操作、账户管理、权限控制、环境变量、网络配置、远程登录等，逐步摆脱对图形化界面的依赖。
  3. CI/CD认识：我通过GitHub Actions实践了CI/CD理念，理解了自动化构建与部署，为后续开发打下基础。
  4. 多机互连和局域网：我通过虚拟机多机组网实验，直观理解了NAT、Host-Only网络模式、静态IP、hosts解析等网络概念。

5.2 思想层面感悟

  1. 命令行思维的转变：从图形化界面的”点击操作”转向命令行的”指令思维”，这对于一个计算机专业的学生至关重要。
  2. 系统化思维培养：从手动部署到CI/CD流水线，我认识到现代工作核心是将重复劳动进行自动化，从而提升效率与可靠性。
  3. 持续学习：然而现在，我对于整个部署仍具有很多的不理解的内容，以及很多的拓展知识没有去理解，很多疑问也都没有解决，这些我都会在后面一点一点学习解决。

5.3 后续改进方向

  1. 深入学习Hexo与静态站点生成器的底层实现原理
  2. 尝试Docker容器化技术，进一步提升部署的标准化程度
